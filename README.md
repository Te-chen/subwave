# subwave

YouTube 视频 → 中文硬字幕。**只做字幕翻译与压制**，不重新转录语音。

适用于**任何自带字幕（原生或自动生成）的视频**：直接复用平台的字幕时间轴，跳过 Whisper 转录这一步——省掉最大的算力开销，也避免转录误差。

---

## 为什么这样做

主流搬运管线（yt-dlp → Whisper 转录 → 翻译 → 压制）在 Whisper 上花掉大部分时间。但如果视频本身已有字幕，转录就是重复劳动，而且引入了自己的时间戳误差。

`subwave` 的前提是：**平台字幕已经带词级时间戳，翻译精度只取决于翻译本身**。

代价是必须处理平台字幕的两类坑，这也是本项目存在的理由：

1. **滚动字幕结构**。YouTube 的 json3 里，`aAppend` 事件只是换行标记，不是内容；真正的字幕被切成半句片段，词与词分散在不同事件里。
2. **碎片化翻译**。把半句片段直接喂给翻译模型，模型会合并句子，返回行数对不上，字幕就整体错位。

`subwave` 的解法是**句子级对齐**：英文按标点切子句，中文按同样标点切，子句数一致就逐子句映射到英文的真实时间戳，不一致才退回按字数分配。

## 安装

```bash
git clone https://github.com/<you>/subwave.git
cd subwave
pip install -r requirements.txt
```

需要 `ffmpeg` 与 `ffprobe` 在 PATH 中。字体默认使用系统 SimHei（Windows）或 Noto Sans CJK（Linux）。

---

## 快速开始

```bash
export DEEPSEEK_API_KEY=sk-...

python -m subwave prepare ./raw/brain-duster      # 拿字幕 + 建索引
python -m subwave make    ./raw/brain-duster --lang zh-CN
```

输出默认写到 `./out/<creator>/<lang>/`。

---

## 目录约定

输入目录里的视频**只读**，输出永远写到别处：

```
raw/
  brain-duster/          <- 只读
    2026-10-18 - Title [VIDEOID].mp4
  mass-influence/
    ...

out/
  brain-duster/          <- 按创作者分层，避免不同频道混在一起
    zh-CN/
      zh-CN - 2026-10-18 - Title [VIDEOID].mp4
  mass-influence/
    zh-CN/
      zh-CN - ...
```

命名规则：保留原文件名，前面加 `<lang> - ` 前缀。原文件名里的 `[VIDEOID]` 会被自动识别用于抓字幕。

## 核心设计

### 字幕来源

优先 `en-orig`（原始音轨语言），退回 `en`，再退回目标语言相关的自动字幕。抓不到字幕的视频会被跳过并在报告里列出，不会静默产出。

### 自适应尺寸

不假设 16:9。每个视频独立探测：

| 探测项 | 方法 |
|---|---|
| 分辨率 | `ffprobe` |
| 画面实际底部 | `cropdetect` 找非黑区域，画面下方的黑边就是字幕区 |
| 字号 | 按画布宽度等比缩放（`width × 0.0426`），保证不同分辨率下每行字数一致 |
| 字幕垂直位置 | 落在黑带内并按带宽比例定位 |

这让同一套参数同时适配 1080×1920 竖屏、1920×1080 横屏、576×1024 低分辨率，以及有余量的宽银幕。

### 时间轴

1. 解析词级时间戳；缺失的用相邻锚点线性插值。
2. 按句子边界聚合（句末标点，且排除 `Mr.` `No.` 等缩写）。
3. 英文按 `, ; :` 切子句，记录每个子句的真实起止。
4. 中文按 `，；：、` 切子句。
5. 子句数一致 → 逐子句映射；否则按字数比例分配。
6. 全局去重叠：优先压缩前一条，压到最短则顺延后一条起点。

### 宽度控制

用 PIL 实测像素宽度，不按字数猜。超宽时的切分顺序是：

1. 优先落在标点处（`，；：、`）
2. 无标点时**向中点均衡切**，而不是贪心填满
3. 切点若落在拉丁词内部（如 `USDA`），回退到词首
4. 切出来只剩标点时并回上一条，避免 `"。"` 这种孤儿字幕

第 2 条是实际踩出来的：贪心最大化第一行，切点必然落在额度耗尽处，中文里那就是词中间——`美国农业部营养部门的主管` 被切成 `…美国农业部` + `门的主管`。均衡切分仍然不知道词边界（中文无法靠空格判断），但失败模式从"语义断裂"降级为"断得略早"，肉眼几乎不察觉。

切片保持连续，拼接可还原原文（含空格）。

## 命令

```bash
# 抓取字幕并生成清单
python -m subwave prepare <dir> [--recursive]

# 生产（默认跳过已存在的输出）
python -m subwave make <dir> --lang zh-CN [--limit N] [--force] [--dry-run]

# 用自定标题命名（映射 video id -> 输出文件名）
python -m subwave make <dir> --lang zh-CN --names titles.json

# 复用已下载的字幕，不访问平台
python -m subwave make <dir> --lang zh-CN --captions-dir ./captions

# 质量门禁（用了 --names 时同样要带上）
python -m subwave verify <dir> --lang zh-CN --names titles.json
```

`--names` 接受两种格式：`{"video_id": "文件名.mp4"}`，或对象数组（每项含 `video_id` 与 `filename`）。这样可以让输出以人工审定的标题命名，而不是照抄源文件名。

`make` 支持断点续跑：已存在且通过校验的输出会被跳过。

---

## 质量门禁

`verify` 检查的是会导致成品不可用的问题，不是风格偏好：

- 输出与源一对一；用了 `--names` 时按映射匹配，并报告映射外的多余文件
- 每条输出可被 ffprobe 解析（`moov atom` 存在，非半截文件）
- 含视频流与音频流，时长与源一致
- 字幕无空文本、无时间重叠、无超长停留
- 跨多个时间点抽样，确认字幕区域确实有内容

最后两条都是被误报逼出来的：单点采样会落在字幕空隙上，把"有字幕"判成"没字幕"。多采样取最大值才可靠。

## 工程约束（都踩过）

| 约束 | 原因 | 处理 |
|---|---|---|
| ffmpeg 的 `ass=` 不接受 Windows 绝对路径 | 盘符冒号被当作滤镜参数分隔符 | 渲染前切到 ASS 所在目录，滤镜只用文件名 |
| ASS 文件名不能含标题原文 | 引号、冒号、emoji 会破坏滤镜参数 | 用 video id 命名 ASS |
| 渲染必须原子写入 | ffmpeg 最后才写 `moov`，中断留下的文件看似完整却不能播，会被"已存在就跳过"误判为完成 | 写 `.partial`，成功后 `os.replace` |
| 平台字幕端点会触发 bot 校验 | 抓取频率高时要求登录 | `--captions-dir` 复用已下载字幕；生产阶段零网络 |
| 相似度比对要按词归一化 | 字符级比对会被标点/大小写差异放大，把 99.6% 相同的内容判成 41% | 比对文本前统一小写、去标点、按词切分 |

## 已知边界

- **依赖平台字幕存在**。没有字幕的视频不会自动转录——那是另一个工具的事。
- **视频自带硬字幕时不叠加双语**。若检测到画面底部已有文字，只放中文；不做覆盖。
- **翻译质量 = 机器翻译天花板**。适合理解，不等于专业翻译。
- **专名处理靠提示词**，不做术语表。同一人名在不同视频里可能译法不一。
- **不处理多人对话区分**，也不翻译画面内文字。
- **中文没有词边界**，硬切只能做到「不溢出 + 大致均衡」，不能保证切在词之间。有标点的位置优先切标点是更可靠的办法。
